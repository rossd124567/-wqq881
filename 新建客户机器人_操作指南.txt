群组记账助手｜完整源码母版（无品牌客户版）

一、文件用途
accounting_bot.py  机器人完整主程序
requirements.txt  Python依赖
README_部署说明.txt  本版规则与部署摘要
新建客户机器人_操作指南.txt  新客户复用步骤
.env.example  环境变量示例（不是实际密钥）
.gitignore  防止上传数据库、Token等本地文件

二、每新建一个客户机器人
1. 通过 Telegram 的 @BotFather 创建新机器人，获取新的 BOT_TOKEN。
2. 在 GitHub 新建一个私人仓库，上传本压缩包解压后的代码文件。
3. 在 Railway 创建新项目并连接该客户自己的 GitHub 仓库。
4. 设置环境变量：
   BOT_TOKEN = 该客户新机器人的 Token
   ACCOUNTING_DB = /data/accounting.sqlite3
5. 给 Railway 该服务添加持久化 Volume，挂载路径设为 /data。
6. 启动命令设为：python accounting_bot.py
7. 部署成功后将机器人拉进测试群，并按需要授予读取群消息的权限；如需处理普通群消息，检查 BotFather 隐私模式设置。
8. 先测试：回复成员 +300、回复成员 -300、无回复 +300 的提示、普通算式、账单、汇率和日切。

三、哪些地方通常需要修改
- 必改：BOT_TOKEN（Railway 环境变量中，不要写死到代码里）
- 必须独立：每个客户的 Railway 服务和持久化数据库
- 可选：机器人在 BotFather 的显示名称、头像、简介
- 可选：修改代码中的提示语、按钮、账单排版

四、重要注意事项
- 同一 Token 不要同时在两个部署中运行轮询机器人。
- 不要把实际 Token、真实数据库、客户账单打包发给别人。
- 旧客户升级程序时，备份并沿用其现有数据库和持久卷；不要覆盖数据库。
- 新客户应从空数据库开始，不要复制别人的数据库。
- 本包为源代码母版，不含真实 Token、用户账单或生产数据。
- 已检查 Python 语法，尚未完成线上 Telegram 功能回归测试。
